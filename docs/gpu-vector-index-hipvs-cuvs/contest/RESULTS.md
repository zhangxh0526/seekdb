# AMD CAGRA 构建性能报告

测量日期：2026 年 10 月 30 日（Asia/Shanghai）。

在本次 16 核开发容器的三轮串行配对中，公开 SIFT 子集构建加速几何平均为 **2.854×**，固定种子 256 维代理为 **2.432×**。六组配对均通过开发质量、主键完整性、查询吞吐、显存和重启检查。

这些是实际 Radeon GPU 开发测量。公开子集未认证为组织方的相同子集；256 维代理不是 Hidden250K。正式隐藏集门槛、24 核官方环境下的性能及最终得分仍须由平台验证，本报告没有填写正式分数。

候选保留 FP32、100 轮 NN-descent、128/256 图度数和固定 CAGRA 搜索参数。建图期间为调用线程及内部新线程限制最多 16 个 OpenMP 工作线程，并使等待线程立即休眠；成功或失败后恢复数量和等待设置。真实并发 GPU 建图检查验证了不同调用线程的限制及进程中新线程默认设置的恢复。Linux GPU 构建的内部 pthread 至少保留 1 MiB 栈，以容纳 GPU profiler 静态 TLS。

源码在全新 checkout 和全新 `build_release` 中，使用题目固定的 bridge、CMake 和 build 命令完整构建成功。冻结第三方和 Rust vendor 依赖来自预装离线缓存，没有增加下载依赖。具体命令见根目录 `AMD_CAGRA.md`。

## 环境与测量范围

GPU 报告 gfx1100、约 48 GiB 显存。ROCm 7.2.4、GCC 13.3.0、CMake 3.31.10、Rust 1.97.1、Python 3.12.3。容器可见 128 个逻辑 CPU，cgroup 实际配额为 16 核，主存上限 55 GiB；seekdb 设置 `cpu_count=16`、`memory_budget=8G`。未通过环境变量额外设置 OMP_NUM_THREADS、KMP_BLOCKTIME 或 OPENBLAS_NUM_THREADS。

每轮从新目录、新进程、无向量索引的原始 FP32 表开始。计时从离线建索引开始，到首条查询返回合法结果结束。随后分别运行 4,096 条 Top-10 和 4,096 条 Top-100 单行 SQL，检查每条的 k 个主键合法且唯一。数据准备、导入、真值计算、进程启动和源码编译均在构建计时区间外。

基线和候选同机串行，两个数据集交换运行顺序，第二轮再交换顺序。所有六组有效配对均列在下表，没有选择最快一轮。完整协议见 `BENCHMARK_PROTOCOL.md`；数值及散列见 `MEASUREMENTS.json`。

## 质量、资源与持久化

| 数据集 | 候选 Recall@10 范围 | 候选 Recall@100 范围 | 最大同轮显存比 |
| --- | --- | --- | ---: |
| 公开 SIFT | 0.99990234～0.99995117 | 0.99996826～0.99998047 | 1.000006× |
| 256 维代理 | 0.95021973～0.95109863 | 0.89812744～0.89837402 | 1.000595× |

候选三轮配对的最大进程 HWM 为 3.583 GiB，显存最大采样值为 0.802 GiB。资源采样周期为 100 ms，不保证捕获任意更短的瞬时峰值。cgroup 读数同时包含数据库文件缓存和容器内其他进程，不能将接近 55 GiB 的 cgroup 读数误当作 seekdb 进程私有内存；原始 RSS/HWM 与 cgroup 曲线均保存。

六组配对均实际关闭并重启基线和候选进程，再查询同一持久化索引。原始主键采用 `3*i-700000001`，返回的非连续负主键经过合法性及唯一性检查。重启后 GPU 快照重载和查询均成功。

## GPU 路径

最终候选独立使用 rocprofv3，按 SQL 驱动的单调时钟边界对应 kernel trace。

| SQL 阶段 | NN-descent local_join 内核 | CAGRA 搜索内核 |
| --- | ---: | ---: |
| ddl | 100 | 0 |
| first_query | 0 | 1 |
| top10 | 0 | 16 |
| top100 | 0 | 16 |

profiler 运行中每组后续查询为 16 条；性能和质量配对每组为 4,096 条。profiler 结果用于路径核验，没有纳入普通配对性能统计。建图与搜索使用同一实现，没有按 profiler 或测试阶段切换算法。该证据是本容器上的实际执行，不代表已通过正式平台抽检。

## CPU/GPU 构建对比

同一份公开 SIFT FP32 数据、索引参数和实际首查计时边界下，单次 `lib=vsag` CPU SQL 路径结果如下：

| 路径 | 构建时间（含首查） | Recall@10 | Recall@100 | 重启 |
| --- | ---: | ---: | ---: | --- |
| CPU VSAG，单次 | 82.120 秒 | 0.98098145 | 0.94978027 | 通过 |
| GPU CAGRA，三轮中位数 | 16.337 秒 | ≥0.99990234 | ≥0.99996826 | 通过 |

CPU 构建时间除以候选 GPU 中位数约为 5.027×。CPU 与 GPU 的底层图算法和查询质量不同，CPU 查询延迟也更低；这项单次对比用于展示 CPU 路径仍可用，不是正式性能评分或同算法加速结论。正式优化对比始终是同轮 V5 GPU 与候选 GPU。
