# AMD CAGRA 开发测试协议

本目录记录真实 Radeon GPU 上执行的开发测试。公开数据和固定种子的代理数据均不能替代组织方的 Hidden250K，任何本地计算都不构成正式成绩。

## 输入与真值

- SIFT：ANN-Benchmarks SIFT1M 的前 250,000 条原始向量及前 4,096 条查询，FP32、128 维、平方 L2。该子集不保证等同于组织方选取的 SIFT250K。
- 256 维代理：固定种子 `20261030` 的标准正态 FP32 向量，250,000 条数据及 4,096 条查询。它不是 Hidden250K。
- 主键为 `3*i-700000001`，包含非连续的负数。返回值必须映射到这些真实主键，不能把行偏移当作主键。
- 真值在计时前使用同份 FP32 数组、分块矩阵运算和精确平方 L2 计算。按距离及主键排序；保留原始查询返回，以便复核边界距离并列造成的差异。
- 每份数据的元数据保存原始向量和查询的 SHA-256。`.9g` 十进制文本用于 FP32 SQL 导入和查询，足以往返原始 FP32。

## SQL 与计时

每次使用新的空运行目录、独立进程和数据库，先创建普通表并导入原始向量。通过 `SHOW INDEX` 保存建图前的索引状态。固定索引参数如下：

```sql
CREATE TABLE items(id BIGINT PRIMARY KEY, v VECTOR(128));
CREATE VECTOR INDEX idx_items ON items(v)
  WITH (distance=l2,type=hnsw,lib=cuvs,m=16,ef_construction=200,ef_search=64);
SELECT id FROM items ORDER BY l2_distance(v, <query_vector>) APPROXIMATE LIMIT 10;
```

256 维数据使用 `VECTOR(256)`。`<query_vector>` 表示该次查询的实际 FP32 向量数组；驱动将完整数组写入表达式，原始 DDL 保存为 `ddl.sql`。

构建时间从执行离线 `CREATE VECTOR INDEX` 开始，到首条 Top-10 查询返回 10 个合法且唯一的主键结束。扫描、传输、GPU 建图、同步、持久化及首查均包含在内；源码编译、进程启动、数据准备、导入和真值计算不计入。

随后分别执行 4,096 条单行 Top-10 和 4,096 条单行 Top-100 SQL。QPS 包含 SQL 往返、结果读取和合法性验证；Recall 统计与结果文件写入在查询计时区间外。记录每条查询的返回值、延迟、P95 和整体 Recall。未使用专用批量检索接口代替这些 SQL。

重启检查会真正结束进程，再从同一数据目录启动进程并查询 Top-10/100；返回主键和质量再次接受检查。`lib=vsag` 使用同一 SQL 结构验证 CPU 路径。

## 配对与观测

基线为冻结 V5 `634888d9b037153fa143d2c913ba4b25503e1d62`，使用独立保存的源码构建产物。基线和候选均在同一 GPU 上串行运行，不复用其他轮次的图、索引文件或进程缓存。保留所有有效配对和运行顺序；有编译重叠或 profiler 的运行不纳入普通配对性能结论。

开发容器限额为 16 核、约 55 GiB 内存；seekdb 显式设置 `cpu_count=16`、`memory_budget=8G`。该配置与官方 24 核、96 GB 环境不同，比较仅对同机配对有效。

显存采样只统计容器实际获得的 `/dev/dri` 设备对应的 sysfs 节点。主存同时保存进程 RSS/HWM 和 cgroup 读数；cgroup 读数还包含文件缓存及容器内其他进程。原始资源记录按 100 ms 周期保存，不把采样值冒充绝对瞬时峰值。

GPU 路径通过独立的 rocprofv3 运行采集。驱动的单调时钟阶段边界与 kernel trace 对齐，分别检查 DDL 的 NN-descent、首查和两组单行查询的 CAGRA 搜索。profiler 的耗时不用于普通性能结论。独立 bridge 的诊断记录仅说明该边界，不替代完整 SQL 验证。

## 判断标准

公开 SIFT 的 Recall@10/100 至少为 0.95，且相对同轮基线下降不超过 0.005。代理数据同样检查相对下降，但不宣称满足正式隐藏集门槛。每条查询必须返回 k 个合法且唯一的主键。综合查询比为两组 QPS 比的几何平均，至少为 0.90；采样显存比应不超过 1.25，并单独记录主存、重启和 CPU SQL 结果。

正式分数、隐藏集 Recall 和官方 GPU 抽检只能由平台返回的完整 commit、gates 和加速比确认。
